== System Overview & Micro-Architecture

Linux extended Berkeley Packet Filter (eBPF) provides an in-kernel, register-based virtual machine executing 64-bit instructions with zero context-switch overhead. Programs are statically checked by the kernel verifier before execution.

The core runtime parameters are configured for *production* workloads:

* Runtime kernel version: `{kernel-version}`
* Primary compilation target: `{target-arch}`
* Verification state complexity bound: 1,000,000 processed instructions

=== Rust Wayland Camera Bridge

Below is the zero-copy PipeWire buffer receiver interfacing with the Wayland presentation layer.

[source,rust]
----
use std::os::fd::AsRawFd;
use wayland_client::protocol::wl_shm; <1>

pub struct CameraFramePipeline {
    fd: i32,                          <2>
    stride: usize,
    buffer_pool: wl_shm::WlShm,
}

impl CameraFramePipeline {
    pub fn new(fd: i32, width: u32, height: u32) -> Result<Self, String> {
        let stride = (width * 4) as usize; <3>
        println!("Allocating frame pipeline: {}x{} stride: {}", width, height, stride);
        Ok(Self { fd, stride, buffer_pool: unsafe { std::mem::zeroed() } })
    }
}
----

== Admonitions & Callouts

NOTE: eBPF programs run entirely in ring 0 kernel privilege, but cannot crash the machine due to the verifier's strict pointer validation.

TIP: Compile BPF programs with `clang -O2 -target bpf -g` to preserve BTF debugging information for runtime relocation.

IMPORTANT: Memory barriers (`smp_mb()`, `smp_rmb()`, `smp_wmb()`) are mandatory when communicating through lockless single-producer single-consumer ring buffers.

CAUTION: Unbounded loops are rejected by kernel verifiers prior to Linux 5.3; use `#pragma unroll` or specify explicit iteration limits.

WARNING: Incorrect DMA-BUF synchronization flags may cause visual tearing or display stall bugs under Wayland compositors.

=== Multi-line Admonition Block

[WARNING]
====
Directly dereferencing user-space pointers inside a BPF program without `bpf_probe_read_user()` will result in an immediate verifier rejection error:

`R1 invalid mem access 'inv'`

=== Technical Sidebar

.Sidebar: eBPF Helper Calling Convention
****
eBPF registers map directly to CPU hardware registers on `x86_64`:

* `R0` -> Function return value (`%rax`)
* `R1` - `R5` -> Function call arguments 1 through 5 (`%rdi`, `%rsi`, `%rdx`, `%rcx`, `%r8`)
* `R6` - `R9` -> Callee-saved registers (`%rbx`, `%r13`, `%r14`, `%r15`)
* `R10` -> Read-only frame pointer to top of stack (`%rbp`)
****
